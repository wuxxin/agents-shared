## 5. Oracle D — park-churn under subagent pressure (the reason to adopt the SSD tier)

**Symptom being fixed:** with our generated defaults (`--conversation-cache-slots 8 --conversation-cache-mib 16384 --conversation-cache-min-free-mib 6144 --conversation-cache-min-tokens 4096 --conversation-cache-park-gain 2048 --prompt-cache 6`) the cache evicts **least-recently-active first** (`core/conversation_cache.hpp:591-605`), so an idle main-agent context is the first victim when deep subagent sessions fill the queue. Observed on this host: `parked=8 bytes=8,789,447,664 evictions=31` (2026-11-14 02:45). The slot count binds before the byte budget; park cost ≈ **17.9 KiB/token** (771.9 MB / 43,217 tokens, k8v4) ⇒ a 120k main context ≈ 2.1 GiB, ~7 such slots already exceed 16 GiB. Today an eviction costs a cold re-prefill: 43 k in 16.4 s, **≈47 s at 120k**.

**Test-session shape (required):** the **migration session itself runs on a non-local model — DeepSeek Flash (`deepseek-v4-flash` via API) — for the main session and for every subagent it spawns.** Two reasons, both operational: (1) the migration is user-mediated and includes `systemctl --user restart local-chat-strata` / package reinstall; any omp session served by `qwen3.8-flash-next` **dies with the engine**, so doing this work on the model being replaced kills the work mid-flight; (2) a locally-served session keeps conversations in slots, prefills the shared prefix, and parks/restores state while we measure — it taints every benchmark cell it overlaps. So: switch models first (`/model` → DeepSeek Flash, and subagent/task models likewise), then touch the service. The model under test never serves its own driver; production-shape use of qwen3.8 on omp is verified *after* cutover (§7 step 2), not during measurement.

**Pre-flight (interactive, at the start of every test session — ask the user, do not assume):** request that **Pulse is stopped** and the **omp bridge is disabled** for the run (`OMP_BRIDGE_SETTINGS=/dev/null`), confirm omp's model **and all subagent models are on DeepSeek Flash**, and that no other GPU consumer runs. Pulse/hook traffic adds sub-4096-token requests that never park (the `min-tokens` gate) yet still consume prefill and pollute TTFT; the bridge re-injects user messages into every model call of a tool loop, changing request counts per turn. Record all answers in the run's README (`background:` field). If the user declines to stop them, keep the same settings across *all* arms of that comparison and mark the run `background: pulse+bridge`.

**Protocol (single variable = the persistence mechanism; everything else fixed):**
1. Warm a main conversation to ~120k tokens (Oracle B corpus), let it idle past any park-gain so it is snapshotted.
2. Fire K subagent conversations **from the lab script over HTTP** (no omp session involved), each ≥4,096 tokens and growing, sharing the main conversation's system-prompt prefix, sized so `slots` overflow within 3 turns. **K must exceed the cache slots, not merely look like production:** with `--conversation-cache-slots 8` the production mix is main + 4 workers + LifeOS + hooks, but the lab drives only main + K workers, so **K=5 never overflows (measured 2026-11-20: reuse 100%, `prompt_n=21`, no eviction — the cell proves nothing)**. Use `K >= slots + 1` (K=9) or lower `--conversation-cache-slots` for the experiment; either way verify `parked`/`evictions` counters rose during the burst before accepting the cell. **Do not let workers share main's full prefix when testing eviction:** measured 2026-11-20 with `K=9`, a 120k shared system prompt kept main resident (worker traffic pins the shared prefix) — pressure counters moved (`parks=10 evictions=4 parked=6 bytes=16.77 GB`) while the main probe still reused 99.97% with `prompt_n=42`, so the tier was never asked to restore main. Arms A/B/C therefore use `--share-prefix small` (workers get a ~150-token system prompt), while arms D/E use `--share-prefix full` because prefix pinning is exactly what they measure. A cell without a rise in `evictions`/`parks` during the burst is **invalid**, not passed.
3. Return to the main conversation with a 1-token question; record `usage.prompt_tokens_details.cached_tokens`, engine `timings.prompt_n/prompt_ms`, TTFT, and the conv-cache journal lines our launcher already parses (`parked/bytes/evictions`), plus `/metrics → conversation_cache.refused{reason}`.
4. Repeat 3× per arm, arms interleaved A B B A; fresh main context each cell (never reuse a warm cache across arms).

| Arm | Configuration | Expected signature |
|---|---|---|
D-A | today (`--disk-spill` removed, no tier) | full cold re-prefill: prompt_n ≈ 120k, TTFT ~45-50 s |
D-B | `+ --conversation-spill-dir ~/.cache/user-cache/conv-spill --conversation-spill-mib 24576` | main returns from disk: read-back MiB progress line, prompt_n ≪ 120k, TTFT ~1.5-3 s |

**Pass criteria:** D-B/D-D reach ≥95% prefix reuse on main return with TTFT ≤3 s and zero forced cold prefills >5k tokens in a 30-minute mesh run; `refused{reason="budget"}` drops to ~0 while `short`/`ram_floor` refusals stay explainable. **Explicit non-goal:** the SSD tier is per-engine-process (`<root>/<pid>-<nonce>` + flock; unlocked folders are deleted at start, `conversation_spill.hpp:1-20`) — it does not survive a restart, so the SIGUSR1 `/slots` save path stays our cross-reboot mechanism (and D-C tells us whether batch mode keeps that path at all).

   c. Run verbatim via **`scripts/strata-baseline-cells.sh`** from that isolated instance — it executes Oracle A (`--profile generation --runs 3`) and Oracle B (`--profile mix --prefill-bytes 120000 --runs 6`) against the live service, slices the journal per cell, records rc/duration in `raw/cells.tsv`, and writes a README with hardware/config identity:
      ```bash
      scripts/strata-baseline-cells.sh --out <UTC-date>-gfx1100-<engine>-cells \
          --background "pulse stopped; bridge off (OMP_BRIDGE_SETTINGS=/dev/null); extensions off; driver = deepseek-v4-flash"
      ```
